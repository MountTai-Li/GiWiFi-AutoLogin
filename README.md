# GiWiFi 校园网自动登录助手

> 连上宿舍 WiFi 后自动完成 GiWiFi 门户认证；掉线自动重登；开机静默启动（可选挂托盘图标）；**可拦掉 Windows 自动弹出的浏览器登录页**，全程无需手动打开登录网页。

适用环境：Windows 10 / 11 · 认证网关 `http://192.168.100.3/gportal/`（GiWiFi `gportal` 门户）

**当前版本：v1.13.0**（零第三方依赖 · 常驻约 24 MB · 联网稳态不访问位置信息）

> ⚠️ **使用范围**：本项目用于**自动化你本人校园网账号的登录流程**，属于个人效率工具。
> 请仅在你本人有权使用的账号与网络上运行，并遵守所在学校的网络管理规定。
> 作者不对任何滥用行为及由此产生的后果负责。

---

## 一、它解决什么问题

原始流程：开电脑 → 连宿舍 WiFi → 打开浏览器 → 输入 `http://192.168.100.3/gportal/web/logout?sign=...` → 手动输账号密码 → 才能上网。
每次重连、每次凌晨被踢下线，都要重复一遍。

本程序把这一串操作变成：**开机即联网，掉线自动恢复，你什么都不用做。**

## 二、快速开始（4 步）

1. **双击桌面「GiWiFi自动登录」图标**（安装时已自动创建，开始菜单里也有）。
   全程**不会出现任何命令窗口**。
2. 在界面里填 **校园网账号**（通常是手机号）和 **密码**，点 **「保存并应用」**。

   > **账号和密码会自动保存，下次打开自动填充**，不用每次重输。
   > 密码以 Windows DPAPI 加密存在本机（`config.json` 里只有密文），
   > 界面上默认是掩码 `●●●●●●`，勾右侧「显示」才能看到明文。
3. **「宿舍 WiFi」直接从下拉框里选**，不用手输。

   > 程序会自动扫描附近的 WiFi 并列出信号强度，当前正在连的那条排在最前面并标注「已连接」。
   > 默认是**「不限制」**——大多数情况下保持默认即可，留空/不限制最省心。
   > 列表会过期，点右侧 **「刷新」** 或重新展开下拉框即可重扫。
4. **想让程序自动连上某个 WiFi**，就选中它，再勾上 **「记住并自动连接」**，然后保存。

   > 勾上以后，一旦发现没连在这个 WiFi 上，程序会自动帮你连过去（走 Windows 的无线配置）。
   > ⚠️ 前提是**本机已经保存过这个网络的无线配置文件**——也就是你之前手动连过它。
   > 新网络需要 WiFi 密码才能建立配置文件，程序没法凭空造出来；
   > 这种情况保存时会弹窗提醒你先手动连一次。
   > 选「不限制」时这个勾选框会被自动禁用（无从"连哪一个"）。

> 开机自启在安装时已经开启。如需关闭，点界面上的 **「开机自启：已开启」** 按钮即可切换。

**关于关闭窗口**：点右上角 **×** 只是**把窗口收进系统托盘**，程序继续在后台保持网络在线，
WiFi 认证不会中断。双击托盘图标即可重新打开窗口；右键托盘图标有
「打开主窗口 / 立即登录 / 暂停·恢复监控 / 退出程序」。
要**真正结束程序**，请用界面上的「退出程序」按钮，或托盘菜单里的「退出程序」
（它会连同开机自启的后台实例一起退出）。

**关于开机自启要不要显示托盘（v1.10）**：界面底部有一个勾选框
**「开机自启后显示托盘图标」**，默认**不勾**。
不勾 = 开机后完全静默，托盘区什么都不显示（和以前一样）；
勾上 = 开机后托盘区就有一个图标，悬停能看到当前状态，右键可以直接
「打开主窗口 / 立即登录 / 暂停监控 / 退出程序」，不用再去启动文件夹里找程序。
勾选后**立即生效并写盘**，但它是给**开机自启的后台实例**用的，
所以下次开机（或下次重启程序）才看得到 —— 当前窗口本来就有托盘图标。

**关于「连接 WiFi 时自动弹出的浏览器登录页」（v1.11）**：界面底部还有一个勾选框
**「拦截连接 WiFi 时自动弹出的浏览器登录页（需管理员权限）」**，默认**不勾**。
勾上后会弹**一次** UAC 授权框（因为要写系统注册表），点「是」即完成拦截，
之后连 WiFi 就不会再跳出认证网页 —— 由程序在后台静默认证完成登录。
取消勾选即恢复 Windows 默认行为。**重连一次 WiFi 或重启后完全生效**。
（它为什么会出现、关掉有什么副作用，见「二·五、更新记录」的 v1.11 一节。）

**保存即生效**：点「保存并应用」后配置立刻写入磁盘（原子写 + fsync），
关机、重启、断电都不会丢，不会再弹「已保存」的确认框打断你。

界面上的状态灯含义：

| 颜色 | 状态 | 说明 |
|------|------|------|
| 🟢 绿 | 网络正常 | 已联网，无需干预 |
| 🔵 蓝 | 检测中 / 正在登录 | 正在探测或正在提交认证 |
| 🟡 黄 | 等待启动 / 门户不可达 / 未连校园WiFi | 环境还不满足登录条件 |
| 🔴 红 | 登录失败 / 未配置账号密码 | 看日志里的具体原因 |

**关于启动速度和失败重试（v1.9）**：
开机后会**立即打开 Wi-Fi 并直接发起连接**，一旦网络就绪就立刻继续，不再盲等固定秒数
（日志里会打印「Wi-Fi 准备用时 X 秒」）。若认证失败，程序会**每 5 秒自动重试一次，直到成功**，
并在**首次失败时弹一个提示框告知你**；成功后自动回到 10 秒的正常检测间隔。
不想看到提示框就把 `alert_after_fails` 设成 `0`（只写日志），或设成 `2`/`3`（失败 2/3 次才弹）。

## 二·五、更新记录

### v1.13（本次）—— 「切回宿舍 WiFi」改成可选项，默认关闭

**用户反馈**
> v1.12 里"只要不在校园网里就切回宿舍 WiFi，哪怕当前用手机热点能上网"这个行为，
> 做成可选的按钮，**默认关闭**。

**为什么改成默认关闭**：v1.12 把它做成默认行为，等于程序会**主动断开你正在用的网络**
（手机热点、家里 WiFi）—— 这类"明明能上网却被切走"的操作，必须由用户自己决定。

**改法**

| 配置 | 默认 | 行为 |
|------|------|------|
| `switch_to_target_wifi: false` | **默认** | 只在「**完全没连上 WiFi**」时才自动连接；连的是别的网络且能上网就不去打扰 |
| `switch_to_target_wifi: true` | 勾选 | 只要认证网关不可达（= 不在校园网里）就切回指定 WiFi，**即使当前能上网** |

界面上是 WiFi 那一栏下面的勾选框
**「不在校园网里时切回宿舍 WiFi（即使当前能上网）」**，默认不勾；
没选具体 WiFi（选「不限制」）或没勾「记住并自动连接」时，它是置灰的（没有目标就无从切回）。

**没变的部分**：真正的断线（Wi-Fi 断了 / 手动关了再打开）**永远**会自动连回来 + 认证 ——
那是 v1.12 修的核心 bug，和这个可选项无关。

### v1.12 —— 手动关 Wi-Fi 不再被"抢回去"，断了 2 秒自动重连

**用户反馈**
> 用户手动关 WiFi 再打开、或者断开连接，程序不会自动检测并重连。
> 要求：用户手动关 WiFi 时**不要**自动打开开关；但只要 WiFi 是开着的，
> 就每 10 秒检查有没有连上，没连上就自动连接并登录。

**先看日志找证据**（本机 17:40–17:42 用户复现时的真实日志）：

| 时刻 | 日志 | 问题 |
|------|------|------|
| 17:40:02 | 当前 WiFi 为'未连接'，正在自动连接… | 检测到了，但在连 |
| 17:40:04 | 当前 WiFi 为'未连接'，正在自动连接… | **两个实例同时在连**（后台+界面），互相打断 |
| 17:40:15/17 | 自动连接超时未成功，稍后重试 ×2 | 果然互相打断，两边都失败 |
| 17:41:14 | 当前 WiFi 为'未连接'，正在自动连接… | **整整 60 秒后**才重试（失败退避） |

**四个真实缺陷**

| # | 缺陷 | 旧行为 | v1.12 |
|---|------|--------|-------|
| 1 | 程序会替用户打开 Wi-Fi 开关 | 每 45 秒检查一次，发现关着就**打开**（等于跟用户对着干） | **尊重用户**：只在启动那一刻打开一次，之后你关掉就绝不再碰（`wifi_radio_policy` 可调） |
| 2 | 只有"外网不通"才触发重连 | WiFi 断了但还没走到那一步时不做任何事 | **每轮先看链路状态**（零位置访问），断了立刻连 |
| 3 | 自动连接失败要等 60 秒 | 固定 60 秒冷却，恢复很慢 | 10 秒节奏试 3 次，之后再退避到 60 秒 |
| 4 | 两个实例抢同一个连接 | 两条 `netsh wlan connect` 互相打断，都失败 | 用文件时间戳做**跨进程闸门**，同一时刻只让一个实例下发连接命令 |

**顺带把「位置访问」又降了一档**（v1.8 的老目标没丢）

判断"到底连上没有 / 在不在校园网里"，不再靠查 SSID（那会触发位置访问），改用两个零成本判据：

| 判据 | 用什么 | 会不会触发位置访问 |
|------|--------|-------------------|
| Wi-Fi 开关是开是关 | `WlanQueryInterface(radio_state)` | 否 |
| 链路连上没有 | `GetAdaptersAddresses`（看 IEEE802.11 网卡的 OperStatus / 有无 IPv4） | **否** |
| 在不在校园网里 | 认证网关 `192.168.100.3` 是否可达（纯 TCP） | **否** |
| 到底连的是哪个网络 | `WlanQueryInterface(current_connection)` | 是（只在确认连接结果时查一次） |

> 妙处在于**认证网关是内网地址**：在家、在手机热点上根本不可达。
> 所以"网关可达"就是"我在校园网里"的等价判据，比"SSID 名字像不像"更准。
> 旧实现在一次自动连接里最多要查 **8 次** SSID；现在最多 **1 次**。

**踩的坑：Wi-Fi Direct 虚拟网卡**

用 `GetAdaptersAddresses` 判断链路时，第一次实现「遇到第一个 802.11 网卡就下结论」，
结果永远返回"没连上" —— 本机 Intel 网卡额外挂了两个
`Microsoft Wi-Fi Direct Virtual Adapter`，它们的 `IfType` **同样是 71**，
但状态常年是 Down，而**真实的物理网卡排在它们后面**。必须优先看物理网卡。

**实测**

| 项目 | 结果 |
|------|------|
| 手动关 Wi-Fi 后 | 状态变成「Wi-Fi 已关闭」，**不打开开关、不查 SSID、不戳门户**（日志有明确说明） |
| 自己重新打开 Wi-Fi | 立刻恢复检查（识别"关→开"这个动作并清掉退避），随后自动连接 |
| `netsh wlan disconnect` 模拟断开 | **10 秒内检测到，2 秒内重连成功**（旧版要 60 秒起步） |
| 联网稳态位置访问 | 10 秒窗口内 **0 次**（时间戳无变化） |
| 行为自检（mock 驱动真实循环，12 项） | **12/12 通过** |

**新增配置**

```jsonc
"wifi_radio_policy": "startup",   // startup（默认）| always | never
```

### v1.11 —— 拦掉 Windows 自动弹出的浏览器登录页

**问题**：每次连上宿舍 WiFi，Windows 都会**自动弹出一个浏览器窗口**，把 GiWiFi 认证页
推到面前。可本程序本来就会静默完成认证 —— 这个页面纯属多余，还会打断你正在做的事。

**它到底是谁弹的**（先搞清楚再动手，别瞎关东西）：

Windows 的 **NCSI**（网络连接状态指示器）会周期性发一条**明文 HTTP** 探测：

```
http://www.msftconnecttest.com/connecttest.txt     期望正文正好是 "Microsoft Connect Test"
```

校园网网关会把这条明文请求**劫持、重定向**到认证门户。响应正文对不上，Windows 就判定
「这是个强制门户（Captive Portal）」，然后**按设计主动打开浏览器**把登录页推到你面前 ——
这不是故障，是微软特意做的体验。官方文档原话：

> Windows supports captive portal networks by **immediately opening the web browser**
> when it detects a captive portal.
> —— [Captive Portal Detection and User Experience in Windows](https://learn.microsoft.com/en-us/windows-hardware/drivers/mobilebroadband/captive-portals)（Microsoft Learn）

本机核对过：没装任何校园网客户端，默认浏览器是 Chrome，弹的就是它 —— 所以是纯系统行为。

**怎么拦**：关掉 NCSI 的主动探测，它就不会发现门户，自然也不会弹窗。两处开关都写（都是
微软体系内公开的键，互为兜底），写 HKLM 所以**需要管理员权限**：

| 位置 | 值 | 含义 |
|------|-----|------|
| `HKLM\SOFTWARE\Policies\Microsoft\Windows\NetworkConnectivityStatusIndicator` | `NoActiveProbe = 1` | 官方组策略项「关闭 NCSI 主动测试」 |
| `HKLM\SYSTEM\CurrentControlSet\Services\NlaSvc\Parameters\Internet` | `EnableActiveProbing = 0` | 服务侧主动探测开关（经典做法） |

界面上是一个勾选框：**「拦截连接 WiFi 时自动弹出的浏览器登录页（需管理员权限）」**。
勾选 → 自动提权（弹一次 UAC，点「是」）→ 写入 → 回读校验 → 日志里给你结果。
不想用了取消勾选即恢复 Windows 默认行为。

**实测 & 影响**

| 项目 | 结果 |
|------|------|
| 权限不足时的行为 | 写入返回 `需要管理员权限`，界面**自动发起提权**而不是静默失败 |
| 写入校验 | 写完**回读注册表**确认（NoActiveProbe=1 / EnableActiveProbing=0），不只说"已写入" |
| 生效时机 | 重连一次 WiFi 或重启后完全生效（NCSI 只会在网络状态变化时重新判定） |
| 对任务栏图标 | Windows 不再主动探测 → **可能不再显示「无 Internet」的感叹号** |
| 对依赖 NCSI 的应用 | Microsoft Store、天气等可能判断联网状态偏慢（可以把此项关掉恢复） |
| 对本程序 | **完全无影响** —— 它用的是自己的探测点（`connect.rom.miui.com/generate_204`、`msftconnecttest`），与 NCSI 互不相干 |

> ⚠️ 网上一篇流传很广的「新建 `NoWebBrowserLaunch = 1`」并没有出现在微软任何文档里，
> 本程序不采用未公开的注册表值，只写上面这两个有据可查的开关。

### v1.10 —— 开机自启也能带托盘图标

**问题**：开机自启走的是 `--silent` 纯后台模式，托盘区**什么都不显示**。
好处是干净，坏处是「程序在不在跑、有没有连上」完全看不见，
想打开窗口或临时退出，只能去启动文件夹里找程序再双击一次。

**改法**：新增一个可勾选项 **「开机自启后显示托盘图标」**，勾上之后：

| 行为 | 说明 |
|------|------|
| 开机后托盘立刻出现图标 | 悬停显示当前状态（如「在线 / 正在登录 / 等待启动」），状态一变就更新 |
| 右键菜单 | 打开主窗口 / 立即登录 / 暂停·恢复监控 / 退出程序 |
| 双击图标 | 打开主窗口 |
| 不勾（默认） | 与以前完全一致：**纯静默，托盘区不留任何图标** |

**顺手解决的一个坑：不会出现两个一样的图标。**
后台实例和控制面板各有一份托盘图标，直接打开窗口就会变成两个 GiWiFi 图标。
解决办法是给托盘加了 `set_visible()`（只 `NIM_DELETE` / `NIM_ADD`，
**不销毁窗口和消息循环**，可反复切换），后台实例每秒探一次
「控制面板是否在运行」（读 `Global\GiwifiAutoLogin.Gui` 互斥体）：

```
开机 → 后台实例挂出图标
       ↓ 打开控制面板
    后台图标撤下，控制面板接管图标（全程只有 1 个）
       ↓ 关掉控制面板（× 号或退出）
    后台图标自动放回来
```

**实测**（真机，`tray_on_autostart = true`）

| 场景 | 结果 |
|------|------|
| 后台启动 → 托盘可交互 | 0.0 秒（与进入监控循环同一时刻），日志「已按设置显示托盘图标」 |
| 打开控制面板 → 后台图标撤下 | 1 秒内，日志「控制面板已打开，后台托盘图标已隐藏」 |
| 关闭控制面板 → 后台图标放回 | 3 秒内，日志「控制面板已关闭，后台托盘图标已恢复」 |
| 托盘机制自检（14 项：创建 / 幂等隐藏 / 恢复 / 四个菜单命令 / 状态提示） | **14/14 通过** |
| 内存 / 位置信息访问 | 无变化（托盘是事件驱动的，不进监控循环） |

**新增配置**

```jsonc
"tray_on_autostart": false,   // 开机自启（后台）时是否显示托盘图标；默认 false = 完全静默
```

> ⚠️ 这个选项管的是**开机自启的那个后台实例**，所以在控制面板里勾上时，
> 界面上看不到任何变化（当前窗口本来就有托盘图标），**下次开机才体现**。
> 勾选框会立即写盘，不需要再点「保存并应用」。

**顺手修掉一个 exe 专属的潜伏 bug**

打包成 exe 后，主程序里的「程序目录」原本取的是 `__file__` 所在目录 ——
而 PyInstaller 单文件模式下那是**临时解包目录**（进程一退出就被删掉）。结果：

| 受影响的东西 | 原本的表现 | 现在 |
|--------------|-----------|------|
| 后台模式的关键日志（`_silent_log`） | 写进临时目录，**退出即消失，出问题查不到** | 写到 exe 同目录的 `giwifi.log` |
| 「退出程序」的跨进程标记 | 两个进程临时目录不同，**界面退出时通知不到后台实例** | 同一目录，联动正常 |
| `crash.log` | 同上，崩了没痕迹 | 落在 exe 同目录 |

现在统一按 **exe 所在目录** 解析（与 `giwifi.app_dir()`、`monitor` 的日志路径一致），

### v1.9 —— 启动提速 3 倍 + 认证失败重试与提示

**问题**：开机后要很久才打开 Wi-Fi 并连上网络。

**先从真机日志算出慢在哪**（2026-09-24 09:00:49 那次开机）：

| 时刻 | 事件 | 花费 |
|------|------|------|
| 09:00:49 | 程序启动，开始盲等 | — |
| 09:00:54 | 进入监控循环，**这时才开始**打开 Wi-Fi | **5.0 秒纯等待** |
| 09:00:54 | 已自动打开 Wi-Fi，然后盲等它关联 | **6.0 秒纯等待** |
| 09:01:00 | 开始连接宿舍 WiFi | — |
| 09:01:02 | 连接成功 | 2 秒 |
| 09:01:03 | ❌ 第 1 次认证被拒 | — |
| 09:01:19 | 网络恢复（第 2 次认证成功） | **16 秒指数退避** |

**从启动到联网共 30 秒，其中 27 秒是纯粹的无效等待。**

**改动**

| 问题 | 改法 | 收益 |
|------|------|------|
| 盲等 5 秒才开始开 Wi-Fi | **立即开 Wi-Fi** —— 无线电启动 + 关联恰是最慢的一环，本该最先做 | −5 秒 |
| 开完 Wi-Fi 又盲等 6 秒「让它关联」 | **删掉这段等待** —— 紧接着的连接流程本身就会发起连接并轮询结果，盲等只是干等 | −6 秒 |
| 失败后退避 16 秒（第 1 次）、22 秒（第 2 次）… | **去掉指数退避**，改成固定间隔重试（`retry_interval`，默认 5 秒）直到成功 | −11 秒起 |
| 连接确认轮询 2 秒 × 10 次 | 改成 1.5 秒 × 8 次，**一匹配上就立刻返回** | −8 秒（最坏情况） |
| 打开 Wi-Fi 失败要等满 45 秒节流才能重试 | 失败时只隔 5 秒就重试 | −40 秒（异常场景） |
| 认证失败用户不知情 | **首次失败弹提示**（界面用对话框，后台用原生 MessageBox），然后继续自动重试 | — |

**实测对比**

| 指标 | 改造前 | 改造后 |
|------|--------|--------|
| 启动 → 进入监控循环 | 5.0 秒 | **约 0 秒**（日志会打印「Wi-Fi 准备用时 X 秒」） |
| 首次认证被拒 → 重试成功 | 16.0 秒 | **5.06 秒** |
| 真实门户的实际提交间隔 | — | **6.00 秒**（5 秒重试周期 + 1 秒限频补偿，未触发门户 5 秒限频） |
| 位置信息访问 | 0 次 | **0 次**（回归确认，未被本次改动破坏） |

**为什么实际提交是 6 秒而不是 5 秒**：门户自身限制「5 秒内不能重复提交」，
所以「5 秒重试周期」要配合「6 秒提交闸门」，否则会收到「操作过于频繁」而被拒。
6 秒已经是不触发门户限频前提下的最快节奏。

**新增配置**

```jsonc
"retry_interval": 5,      // 认证失败后每隔几秒重试一次，直到成功
"alert_after_fails": 1,   // 连续失败几次弹提示；0=不弹，1=首次就弹，3=三次后弹
```

> 提醒：开机时**第一次认证经常会被门户拒绝**（日志里 3 次开机都如此），
> 紧接着第 2 次就成功。所以「首次就弹」意味着每次开机都会看到一个提示框。
> 嫌吵可以把 `alert_after_fails` 设成 `2` 或 `3`，设 `0` 则完全静默。

### v1.8

**问题**：程序会持续频繁地访问位置信息（Windows 会记录在
「设置 → 隐私和安全性 → 位置信息 → 最近活动」里）。

**定位过程**：先读系统记录拿到硬证据，再逐个调用 WLAN API、比对注册表里
`LastUsedTimeStart` 的变化，确定到底哪一次调用触发了位置访问：

| 调用 | 是否触发位置访问 |
|------|------------------|
| `WlanEnumInterfaces`（枚举网卡） | 否 |
| `WlanQueryInterface` → `radio_state`（读 Wi-Fi 开关） | 否 |
| `netsh wlan show profiles` | 否 |
| **`WlanQueryInterface` → `current_connection`（取当前 SSID）** | **是** |
| **`WlanScan` + `WlanGetAvailableNetworkList`（扫描附近 WiFi）** | **是** |
| **`netsh wlan show interfaces`（取当前 SSID 的兜底路径）** | **是** |
| `netsh wlan connect`（自动连接） | 是 |

原理：Windows 把「读取 Wi-Fi 信息」视为一次位置访问 —— Wi-Fi 扫描结果
本身就能反推地理位置。

**根因**：`_SSID_CACHE` 的 TTL 是 **3 秒**，而监控循环每 **10 秒**跑一轮 →
缓存必然失效 → **每 10 秒就真实查询一次当前 SSID**，也就是每 10 秒访问一次位置。

**修复**（核心原则：只在「这个值能决定要做什么」时才去取）

| 改动 | 说明 |
|------|------|
| 监控循环改为**在线优先** | 原来的顺序是「先判断 WiFi 是否连对 → 再探测外网」。可**既然已经在线，就不需要登录，知道当前 SSID 毫无用处**。现在把 WiFi 判断挪到「检测到掉线」之后 —— 只有真要决定「直接登录还是先连宿舍 WiFi」时才需要它 |
| 「不限制 WiFi」时**完全不查** SSID | 默认配置下 `wifi_ssid` 为空，登录判断与 SSID 无关，所以整条路径零查询（连掉线时也不查，因为无需判断连的是哪个网） |
| **去掉启动时的自动扫描** | 原来界面一打开就扫一次 WiFi 列表。现在下拉列表**只在用户主动展开下拉框或点「刷新」时**才扫 |
| 「当前 WiFi」显示改为**必要时机**刷新 | 新增 `display_ssid` 开关：窗口**隐藏到托盘 / 后台静默运行时完全不查**；窗口可见时也至少间隔 120 秒；只在窗口重新打开时立刻刷一次 |
| SSID 缓存 3 秒 → **60 秒** | 仅在「限定了 WiFi、掉线需判断」这条路径上生效 |
| 扫描里去掉一次冗余查询 | 原生扫描结果自带 `FLAG_CONNECTED`，不必再单独查一次当前 SSID（那也是位置访问） |
| 死局时拉长周期 | 掉线 + 连的不是目标 WiFi + 无法自动连接 → 重查间隔拉到 60 秒，避免无意义地反复访问 |
| 保留旧行为的开关 | `ssid_query_interval` 默认 `0`（不做周期检查）；设成 `60` 即可恢复「一直主动保持在指定 WiFi 上」的旧行为 |

**实测（拦截 `wlanapi.current_ssid` / `scan_networks` 计数，即真实位置访问次数）**

| 场景 | 修复前 | 修复后 |
|------|--------|--------|
| 不限制 WiFi + 后台静默（默认常态） | 每轮 1 次（35 秒 7 次） | **0 次** |
| 限定 WiFi + 在线 + 后台 | 每轮 1 次 | **0 次** |
| 限定 WiFi + 窗口可见 | 每轮 1 次 | **仅窗口打开时 1 次** |
| 掉线 + 不限制 WiFi | 每轮 1 次 | **0 次** |
| 掉线 + 限定 WiFi（必要时机） | 每轮 1 次 | 每轮 1 次（保留，且有 60 秒死局下限） |
| 界面启动 | 立即扫描 1 次 | **0 次** |

**行为差异（有意为之）**：以前「在线但连的不是宿舍 WiFi」时会主动切到宿舍 WiFi。
现在默认不再这样 —— 已经能上网就没必要折腾，而且那需要持续查位置信息。
想让程序「一直保持在指定 WiFi 上」，把 `ssid_query_interval` 设为正数即可。

  想改成"一直帮你看着开关"或"永远别碰开关"，改 `wifi_radio_policy` 即可。
- **断了就自动连回来（v1.12）**：每 10 秒看一眼链路状态（**零位置访问**），
  一旦发现 Wi-Fi 断了就立刻自动连接 + 认证，实测断开后 **2 秒**重连上（旧版要 60 秒起步）。
- **可选：不在校园网里时切回宿舍 WiFi（v1.13，默认关闭）**：勾上后，
  即使当前连着手机热点/家里 WiFi 且能上网，只要认证网关不可达就切回你指定的宿舍 WiFi；
  不勾（默认）则只在"完全没连上 WiFi"时才自动连接，不去打扰你能上网的状态。
- **启动很快（v1.9）**：不再盲等固定秒数 —— **立即开 Wi-Fi → 直接发起连接 → 轮询结果，一就绪就继续**。
  启动到进入监控循环约 **0 秒**（改造前要盲等 5 秒才开始开 Wi-Fi）。
- **认证失败每 5 秒重试直到成功（v1.9）**：不再用指数退避（原来第 1 次失败要等 16 秒）。
  受门户自身 5 秒限频约束，实际提交间隔约 6 秒。成功后自动回到 10 秒的正常检测间隔。
- **认证失败会弹提示告知用户（v1.9）**：界面用对话框，后台静默模式用原生 Windows 消息框
  （放在独立线程，不会把监控/重试卡住）。每个「失败连续段」只提醒一次；成功后重新武装。
- **保存即生效（v1.6）**：点「保存并应用」立刻落盘（临时文件 + `os.replace` + `fsync`，
  断电也不会写坏配置），**不再弹「已保存」确认框**，只在界面内闪一下 ✓。
- **点 × 只收进托盘（v1.6）**：窗口关闭 ≠ 程序退出，后台继续保持网络在线。
  双击托盘图标重新打开；右键有「打开主窗口 / 立即登录 / 暂停·恢复监控 / 退出程序」。
  用「退出程序」时会**连同开机自启的后台实例一起退出**，不留残留进程。
- **不访问位置信息（v1.8）**：Windows 把「读取 Wi-Fi 信息」算作一次**位置访问**，
  而查当前 SSID / 扫描 WiFi 都会触发它。本程序只在**真正需要它决定做什么**时才取：
  已在线时完全不查（原来每 10 秒查一次）；「不限制 WiFi」时完全不查；
  窗口收进托盘时不刷新显示。实测后台常驻期间位置访问 **0 次**。
- **账号密码永久保存、每次打开自动填充**：密码用 DPAPI 加密落盘，界面自动填入（默认掩码显示，点「显示」看明文）。
- **可选「记住并自动连接」某个 WiFi**：勾上后若发现没连在该网络上，会自动用 `netsh wlan connect` 连过去。
- **宿舍 WiFi 自动扫描 + 下拉选择**：调原生 `wlanapi.dll` 触发全量扫描，列出信号强度，
  当前连接的网络置顶并标注「已连接」；不用手输 SSID。列表默认「不限制」。
  **扫描只在展开下拉框或点「刷新」时发生**（启动时不再自动扫）。
- **全程静默、绝不弹黑框**：GUI 由 `pythonw.exe` 运行；所有子进程（`netsh` 等）都带 `CREATE_NO_WINDOW`
  和 `STARTUPINFO(SW_HIDE)`——注意普通 `subprocess.run` 在无控制台进程里会**给子进程新建控制台窗口**，
  这是「黑框乱闪」的典型原因。
- **界面永不卡死**：所有网络请求 / 子进程都在后台线程，Tk 主循环只做界面刷新。
- **内存轻量（v1.7）**：用 `-S` 启动跳过 `site` 模块、`urllib` 按需加载、取 SSID 走原生 API 不起子进程。
  后台常驻 **约 24 MB**（改造前 33 MB），且**不产生任何子进程**。
- **开机自启**：往「启动」文件夹放一个指向 `pythonw.exe` 的快捷方式，后台静默运行。
- **开机自启可选带托盘（v1.10）**：勾上「开机自启后显示托盘图标」后，后台实例也会挂出托盘图标
  （悬停显示实时状态，右键可打开窗口 / 立即登录 / 暂停 / 退出）；默认不勾 = 完全静默。
  打开控制面板时后台会自动把自己的图标撤下，**全程只有一个图标**。
- **可拦掉自动弹出的浏览器登录页（v1.11）**：Windows 的强制门户探测（NCSI）一发现校园网
  被劫持就会主动打开浏览器推认证页，和本程序的功能重复。勾上「拦截连接 WiFi 时自动弹出的
  浏览器登录页」即可关掉这个探测（写注册表，需一次 UAC 授权），之后连 WiFi 不再弹网页。
  副作用是任务栏可能不再显示「无 Internet」感叹号，对本程序毫无影响。
- **密码加密存储**：用 Windows DPAPI（`crypt32.dll`）加密，密钥绑定当前 Windows 用户。别人哪怕把 `config.json` 拷走也解不开。**密码明文不回显到界面**。
- **登录限频**：门户有频率限制（实测会返回「操作过于频繁，请 5 秒后再试！」），
  程序强制两次真实请求间隔 ≥ 6 秒（这是不触发门户限频前提下的最快节奏）。
  限频用**文件时间戳**实现，因此即使「开机自启的后台实例」和「你手动打开的界面」同时存在，也不会一起去冲门户。
- **单实例互斥**：命名互斥体防止重复启动，不会出现两个进程抢着登录。
- **日志轮转**：`giwifi.log` 超过 512 KB 自动滚动为 `giwifi.log.1`。
- **零第三方依赖**：AES 加解密、图标生成、托盘、快捷方式创建全部自带实现，不需要 `pip install` 任何东西。

## 四、登录协议是怎么逆向出来的

GiWiFi 的 `gportal` 门户不是普通的「表单 POST」，密码是**先整体 AES 加密再提交**的。完整流程如下。

### 1. 取登录页，拿隐藏字段

```
GET http://192.168.100.3/gportal/web/login?has_reload=1
```

返回的 HTML 里有一个 `<form id="frmLogin">`，包含 12 个字段。程序按 **DOM 顺序**解析（顺序要和 `jQuery.serialize()` 一致）：

```
nasName=<网关名>   nasIp=   userIp=<你的内网IP>   userMac=
ssid=   apMac=   pid=<分组id>   vlan=
sign=<页面动态生成的签名>      iv=<16 字符的随机向量>
name=<账号>   password=<密码>
```

`sign` 和 `iv` 每次刷新都会变，**必须实时抓取**，不能写死。同时要带上 `PHPSESSID` Cookie。

### 2. 序列化后整体加密

页面里的真实代码（从 `login_page.html` 里提取的原文）：

```javascript
function cryptoEncode(data){
    var iv  = $("#iv").val();
    var key = CryptoJS.enc.Utf8.parse('1234567887654321');
    var ivv = CryptoJS.enc.Utf8.parse(iv);
    var encrypted = CryptoJS.AES.encrypt(data, key,
        { iv: ivv, mode: CryptoJS.mode.CBC, padding: CryptoJS.pad.ZeroPadding });
    data = encrypted.toString();
    return {'data': data, 'iv': iv};
}

// 登录
var msg = cryptoEncode($("#frmLogin").serialize());
$.ajax({
    url : "/gportal/web/authLogin?round=" + Math.round(Math.random() * 1000),
    data : msg,  type : "post",  dataType : "json", ...
```

要点：
- 加密对象是 **整个序列化后的 query string**，不是只加密密码；
- **AES-128-CBC**，key 硬编码为 `1234567887654321`，IV = 页面返回的 `iv`；
- padding 是 **ZeroPadding**（补 `0x00` 到 16 字节整数倍）；
- 输出 **Base64**，作为 `data` 参数提交，同时把 `iv` 明文一起提交。

### 3. 提交认证

```
POST http://192.168.100.3/gportal/web/authLogin?round=<0~1000>
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
X-Requested-With: XMLHttpRequest
Origin: http://192.168.100.3
Referer: http://192.168.100.3/gportal/web/login?has_reload=1
Cookie: PHPSESSID=...

data=<Base64 密文>&iv=<iv>
```

### 4. 响应判定

```json
{"status":1, "info":"...", "data":{"redirectUrl":"..."}}          ← 成功
{"status":0, "info":"认证拒绝", "data":{"resultCode":2,"reasoncode":1}}  ← 失败
```

`reasoncode` 是业务错误码（从页面 JS 里可读出含义）：

| reasoncode | 含义 |
|-----------|------|
| 1 | 认证拒绝（账号或密码错误） |
| 32 | 该账号还未设置密码 |
| 40 | 需要先完善个人信息 |
| 41 | 需要先绑定手机号 |
| 43 | 需要重新绑定设备 MAC |

### 5. 正确性验证方法（重要）

无法直接用真账号测试时，可以**用假账号做对照实验**，从服务端的错误层级反推报文格式是否正确：

| 提交内容 | 服务端响应 | 结论 |
|---------|-----------|------|
| 完整正确报文（假账号） | `{"reasoncode":1,"info":"认证拒绝"}` | ✅ 解密、签名校验全通过，已进入 AAA 认证环节 |
| IV 用错 | `error: sign is empty` | 解密失败 → 证明服务端确实在做 AES 解密 |
| `data=QUJD`（非法密文） | `error: userName is empty` | 解析失败 |
| `data` 为空 | `error: userName is empty` | 参数缺失 |

只要第一种能一路走到 `reasoncode` 这一层，就证明加密方式、序列化顺序、参数编码全部正确。这一步不需要知道真实密码。

## 七、config.json 说明

```jsonc
{
  "username": "13800138000",         // 校园网账号（手机号），界面保存时写入
  "password_enc": "<DPAPI 密文，保存时自动生成>",   // 不要手动改
  "portal": "http://192.168.100.3",  // 认证网关
  "login_path": "/gportal/web/login",
  "auth_path": "/gportal/web/authLogin",
  "check_interval": 10,              // 在线时的检测间隔（秒）
  "retry_interval": 5,               // 认证失败后的重试间隔（秒），一直重试到成功
  "alert_after_fails": 1,            // 连续失败几次弹提示；0=不弹，1=首次就弹
  "timeout": 8,                      // 单次请求超时
  "probe_timeout": 4,                // 连通性探测超时
  "startup_delay": 5,                // 等 Wi-Fi 就绪的**上限**秒数（一就绪就立刻继续）
  "wifi_ssid": "",                   // 限定 WiFi 名称/前缀，留空=不限制
  "ensure_wifi_on": true,            // 启动后自动打开 Wi-Fi 开关（无线电）
  "wifi_radio_policy": "startup",    // 开关策略：startup（默认）/ always / never，见下
  "auto_connect_wifi": true,         // 没连上指定 WiFi 时自动连过去
  "switch_to_target_wifi": false,    // 不在校园网里时也切回指定 WiFi（默认关，见下）
  "wifi_profile": "",                // 自动连接用的无线配置文件名称（保存时自动解析）
  "tray_on_autostart": false,        // 开机自启（后台 --silent）时是否显示托盘图标
  "ssid_query_interval": 0,          // 0=不做周期性 WiFi 检查（省位置访问）；>0 才周期查
  "ssid_display_interval": 120,      // 界面「当前 WiFi」的刷新间隔（窗口隐藏时不刷新）
  "log_file": "giwifi.log",
  "probe_urls": [                    // 连通性探测点（204/connecttest 最可靠）
    "http://connect.rom.miui.com/generate_204",
    "http://www.msftconnecttest.com/connecttest.txt"
  ]
}
```

**关于密码字段**：
- 只有 `password_enc` 这一个键（DPAPI 密文）。程序**不会**写出明文 `password` 键。
- 不提供任何「查看明文密码」的入口——界面上的密码框永远是空的，想改密码就重新输入。
- 密文与「本机 + 当前 Windows 用户」绑定：换电脑、换用户、重装系统后都无法解密，需要重新填写。
- 万一手动往 `config.json` 里写了明文的 `password` 字段，程序仍能识别，但界面会**黄字警告**提示你重新保存以加密。

**关于宿舍 WiFi 字段（`wifi_ssid`）**：
- 界面里是**下拉选择**，存的是 SSID 本身（例如 `GiWiFi-xxx-5G`）；选「不限制」则存空字符串。
- 也支持填**前缀**（例如只写 `GiWiFi`），会匹配所有以它开头的网络。
- 匹配规则：完全相同、或者以配置值开头、或者**去掉 2.4G/5G 后缀后相同**，都算命中。
  所以选了 `GiWiFi-xxx-5G`，笔记本切到 2.4G 的 `GiWiFi-xxx` 也照样登录。
- **建议保持「不限制」**：只在「担心在家里/热点上也去尝试校园认证」时才需要限定。
  一旦限定而当前 WiFi 不匹配，程序会进入「未连接校园WiFi」状态并**跳过登录**（不会去试错）。
  但如果你勾了「记住并自动连接」，程序会先尝试自动连过去，连上后再正常认证。
- **为什么不每轮都查 SSID**：查「当前 SSID」在 Windows 上会被记成一次**位置访问**（见 v1.8 说明）。
  所以程序**根本不靠 SSID 来判断该不该登录**，而是问两个零成本的判据（v1.12）：
  ① 链路连上没有（IP 层网卡状态）；② 认证网关是否可达（纯 TCP，内网地址，在家/热点上不可达）。
  只有**确认刚连上的到底是不是目标网络**时，才查一次 SSID。
  默认 `ssid_query_interval = 0` 即「不做周期性 SSID 检查」，**联网稳态位置访问为 0 次**。
  想让程序"死盯着必须连在指定 WiFi 上"（哪怕已经能上网也要求名字匹配），
  把它设成 60 之类的正数即可恢复旧行为 —— 代价是周期性的位置访问。

**关于「记住并自动连接」（`auto_connect_wifi` / `wifi_profile`）**：
- 勾上后保存时，程序会自动去 `netsh wlan show profiles` 里找匹配的无线配置文件并写进 `wifi_profile`。
- 运行时若发现当前 SSID 不匹配，就 `netsh wlan connect name=<配置文件>`，然后每 1.5 秒轮询一次、
  最多等约 12 秒确认是否连上（**一匹配上就立刻返回**）；失败后 60 秒内不再重试（冷却）。
- ⚠️ v1.9 起：**默认只在「检测到掉线」时才做这个 WiFi 判断**（见下方 `ssid_query_interval`）。
  想让程序一直主动保持在指定 WiFi 上，把 `ssid_query_interval` 设成 60 即可恢复旧行为。
- ⚠️ **硬限制：只能自动连接「本机已经保存过无线配置文件」的网络**。
  也就是说你必须在这个电脑上**手动连过一次**该 WiFi。新网络需要 WiFi 密码才能生成配置文件，
  程序无法凭空创建（这是有意的——程序不应该去碰你的 WiFi 密码）。
  如果选了一个没有配置文件的网络，保存时会弹窗提醒你先手动连一次。

**关于「Wi-Fi 开关策略」（`wifi_radio_policy`，v1.12）**：
- 管的是**无线电软开关**（相当于 Win11 的 Wi-Fi 总开关），不是"连哪个网络"。
- `startup`（**默认**）：只在**程序启动那一刻**发现开关关着才帮你打开一次
  （= v1.4 就有的「开机自动开 Wi-Fi」）；**之后你手动关掉，它绝不再碰**。
- `always`：发现关着就打开（v1.11 及以前的行为 —— 用户反馈"我关掉它又给我打开了"，
  所以改掉了默认值）。
- `never`：永远不碰开关（等价于 `ensure_wifi_on: false`）。
- 无论哪种策略：**只要 Wi-Fi 是开着的，程序就每 10 秒检查一次连接状态，
  断了自动重连 + 认证**（见 v1.12 更新记录）。

**关于「切回宿舍 WiFi」（`switch_to_target_wifi`，v1.13，默认关闭）**：
- 管的是**"我已经连着别的网络、而且能上网"时要不要换回宿舍 WiFi**。
- `false`（默认）：只在**完全没连上 WiFi** 时才自动连接。你连着手机热点/家里 WiFi 时，
  程序不会去断你的网（哪怕它知道那不在校园网里）。
- `true`：只要**认证网关不可达**（= 不在校园网里）就切回指定 WiFi，即使当前能上网。
- 判据仍然是零位置访问的「认证网关是否可达」（内网地址，在家/热点上不可达），
  且连续两轮不可达才动手，避免门户抖动导致误切。
- 界面位置：WiFi 那一栏下面的勾选框「不在校园网里时切回宿舍 WiFi（即使当前能上网）」。
- ⚠️ 真正的**断线**（Wi-Fi 断了、你手动关了又开）永远会自动连回来 + 认证，
  和这个开关无关 —— 那是 v1.12 修的核心 bug。

**关于「开机自启后显示托盘图标」（`tray_on_autostart`，v1.10）**：
- 只管**开机自启的那个后台实例**（`--silent`）。`false`（默认）= 完全静默、托盘区无图标；
  `true` = 开机后立刻有图标，悬停显示状态，右键可「打开主窗口 / 立即登录 / 暂停·恢复监控 / 退出程序」。
- 界面上勾选后**立即写盘**，不用再点「保存并应用」；但要**下次开机**（或下次重启程序）才体现。
- 托盘菜单「打开主窗口」是**另起一个带界面的进程**（不是把后台实例变成窗口），
  两者靠文件锁限频，不会一起去冲门户。
- 两个实例的图标不会同时出现：后台实例每秒探一次控制面板是否在运行，
  在窗口打开期间把自己的图标撤下（`NIM_DELETE`），窗口关掉后再放回来（`NIM_ADD`），
  **全程只有一个图标**。

**关于账号密码**：
- 账号和密码都会自动填充，**不用每次重输**。密码经 DPAPI 加密后写进 `password_enc`。
- 界面上密码默认是掩码 `●●●●●●`；想看明文就勾右侧「显示」（看完建议取消勾选）。
- `config.json` 里**永远不会有明文密码**；DPAPI 的保护范围是本机 + 当前 Windows 用户。

**为什么要限定 WiFi 名称？** 如果担心在家里/热点上也去尝试校园认证，可以把 `wifi_ssid` 填成 `GiWiFi`（支持前缀匹配，能匹配 `GiWiFi-xxx`、`GiWiFi-xxx-5G`）。留空则不做限制，最省心。

## 八、打包成 exe / 分发给别人

### 已验证可用的构建命令

```bat
:: 用装了 pyinstaller 的解释器执行
python -m PyInstaller --noconfirm --clean --onefile --noconsole ^
    --name GiwifiAutoLogin ^
    --icon "<绝对路径>\giwifi.ico" ^
    --add-data "<绝对路径>\vendor;vendor" ^
    --add-data "<绝对路径>\giwifi.ico;." ^
    "<绝对路径>\GiwifiAutoLogin.pyw"
```

产物 `dist\GiwifiAutoLogin.exe`，约 11 MB，**单文件、无需 Python 环境**。

**踩坑记录**：
- `--add-data` 的相对路径是按 **`.spec` 所在目录**解析的，不是当前工作目录。
  配合 `--specpath` 使用时必须写绝对路径，否则报
  `ERROR: Unable to find '...\vendor' when adding binary and data files`。
- `.pyw` 入口 + `--noconsole` 用的是 `runw.exe` 引导器，运行时 `sys.stdout` 是 `None`；
  Python 的 `print` 在 stdout 为 None 时是**静默空操作**，不会抛异常（这点可以放心）。
- 冻结后 `autostart.app_dir()` 会自动改用 `sys.executable` 的目录（也就是 exe 所在目录），
  所以 `config.json` / `giwifi.log` 都落在 exe 旁边；
  `icon_path()` 返回 `None`，快捷方式直接复用 exe 内嵌图标，避免指向临时解包目录。

### 一键出包（推荐）

改完代码不用手敲上面那串命令，直接跑：

它会自动完成：PyInstaller 构建 → 组装分发包目录 → **用真实的账号与密码密文做全文比对**

`GiWiFi自动登录助手.zip` 放到桌面。

## 九、常见问题

**Q：状态一直是「门户不可达」？**
说明连不上 `192.168.100.3`，通常是没连上校园 WiFi。检查 `config.json` 里的 `portal` 地址是否正确。

**Q：状态是「登录失败：账号或密码错误」？**
先在浏览器里手动登录一次确认账号密码。若浏览器能登而程序不能，跑 `python GiwifiAutoLogin.pyw --diag` 看能否正确解析出 `sign` / `iv`（门户改版会导致字段变化）。

**Q：日志里出现「操作过于频繁」？**
程序已做 6 秒限频，正常不会触发。如果频繁出现，把 `check_interval` 调大一些。

**Q：换了宿舍楼 / WiFi 名变了怎么办？**
默认 `wifi_ssid` 是空的，不限制 WiFi；只要还能访问认证网关就照常工作。若你填了具体的 SSID，改成新的或清空即可。

**Q：下拉框里没看到我的宿舍 WiFi？**
1. 点右侧 **「刷新」** 重扫一次（结果最多缓存 10 秒，重复点不会空刷）。
2. 展开下拉框时也会自动重扫一次。
3. 如果列表**完全是空的**：检查笔记本的无线开关 / 飞行模式，以及 WLAN AutoConfig 服务是否在运行。
4. **其实不选也行**：保持默认「不限制」，程序在任何 WiFi 下都会尝试认证，这是最省心的用法。

**Q：怎么彻底卸载？**
1. 点界面「开机自启」关掉；或运行 `python autostart.py uninstall`
2. 删除整个 `GiwifiAutoLogin` 文件夹即可（不写注册表、不装服务）。

**Q：密码会不会泄露？**
`config.json` 里只有 DPAPI 密文，且只有**本机本用户**能解开。换一台电脑或换用户，密文失效，需要重新填写。
界面打开时会**自动填充**已保存的密码，但默认掩码显示，不主动点「显示」看不到明文。
DPAPI 不可用时程序会直接拒绝保存，而不是偷偷写成明文。

**Q：密码会不会哪天又「丢」了？**
不会。账号密码都写进了 `config.json`（密码是密文），打开界面就自动填回来。
保存后输入框也不会被清空。就算你手动清空后点保存，程序也会保留原来的密文而不是抹掉它。
想看存储状态，密码框下方有绿色提示「🔒 账号密码已加密保存在本机，每次打开自动填充」。

**Q：勾了「记住并自动连接」，但它没有自动连上？**
检查两点：
1. **本机是否保存过这个 WiFi 的无线配置文件**——也就是你之前有没有在这台电脑上手动连过它。
   命令行核对：`netsh wlan show profiles`。没有配置文件时程序无法自动连接（保存时会弹窗提醒）。
2. 勾选框是否真的勾上了、并点了「保存并应用」。选「不限制」时勾选框是禁用的。

**Q：会不会出现两个实例同时登录？**
- 后台 `--silent` 实例有单实例互斥，不会重复。
- 界面另有独立的互斥（可以和后台上实例共存，方便你改配置）。
- 两者之间用 `giwifi.throttle` 文件做**跨进程限频**，所以即使同时存在，也只有一个会真正去请求门户。

**Q：点右上角 × 之后，程序是不是就退出了？**
没有。**× 只是把窗口收进系统托盘**，后台监控继续跑，网络不会断。
双击托盘图标可重新打开窗口；右键托盘图标有「打开主窗口 / 立即登录 / 暂停·恢复监控 / 退出程序」。
要**真正结束程序**，请用界面上的「退出程序」按钮或托盘菜单里的「退出程序」——
它会连同开机自启的后台实例一起退出，不留残留进程。

**Q：开机自启之后，为什么托盘里什么图标都没有？/ 我想让它显示图标怎么办？**
这是默认行为：开机自启用的是 `--silent` 纯后台模式，**默认完全静默、托盘区不留图标**（v1.10 之前一直如此）。
想让它显示，打开控制面板，勾选底部的
**「开机自启后显示托盘图标（右键可打开窗口 / 立即登录 / 退出）」**（勾上即保存，不用再点「保存并应用」）。
勾上后**下次开机**托盘区就有图标了（悬停显示实时状态，右键/双击可操作）。
注意：当前打开的这个窗口本来就有托盘图标，所以勾选时看不到变化，这是正常的。

**Q：会不会出现两个一样的托盘图标？**
不会。后台实例每秒探一次「控制面板是否在运行」（读 `Global\GiwifiAutoLogin.Gui` 互斥体），
窗口打开期间会把自己的图标撤下，窗口关掉后再放回来，**任何时刻都只有一个图标**。

**Q：我手动把 Wi-Fi 关掉了，程序会不会又给我打开？**
**不会**（v1.12 起）。程序只在**启动那一刻**发现开关关着才打开一次（= 开机自动开 Wi-Fi）；
之后你手动关掉，它就进入「Wi-Fi 已关闭」状态等你，同时日志里会写一句
「这是你的操作，程序不会替你打开」。你重新打开 Wi-Fi 后，它会在 10 秒内检测到并自动连接 + 认证。
想改成旧行为（发现关着就打开）就把 `wifi_radio_policy` 改成 `always`；
想让它**永远**别碰开关就改成 `never`。

**Q：我连着手机热点/家里 WiFi，程序会不会把它切掉？**
**默认不会**（v1.13 起）。默认只在「Wi-Fi 完全没连上」时才自动连接。
如果你**希望**"不在校园网里就切回宿舍 WiFi"（哪怕当前能上网），
勾上 WiFi 那一栏下面的 **「不在校园网里时切回宿舍 WiFi（即使当前能上网）」**
（或把配置里 `switch_to_target_wifi` 设成 `true`）。

**Q：断开 Wi-Fi 之后多久会自动重连？**
**10 秒内检测、通常 2 秒内连上**（v1.12 实测：`netsh wlan disconnect` 后 2 秒恢复）。
旧版本要等 60 秒冷却起步，而且如果同时开着控制面板，两个实例还会抢同一条连接把彼此打断（已修）。
失败会按 10 秒节奏试 3 次，之后退避到 60 秒（信号范围外不用白试）。

**Q：为什么程序不再每次都检查我连的是哪个 WiFi？**
因为查 SSID 会被 Windows 记成一次**位置访问**。v1.12 改用两个零成本判据代替它：
**链路连上没有**（IP 层网卡状态）和**认证网关是否可达**（纯 TCP）。
后者更准 —— 网关是内网地址，在家/热点上根本不可达，"网关可达"就等于"我在校园网里"，
比"SSID 名字像不像"更接近真正的判据。只有确认刚连上的网络时才查一次 SSID。

**Q：为什么连上 WiFi 会自动弹出一个浏览器登录页？怎么关掉？**
这是 **Windows 自己**弹的，不是本程序。Windows 的强制门户探测（NCSI）会明文请求
`http://www.msftconnecttest.com/connecttest.txt`，校园网网关把它劫持到认证门户，
Windows 一发现"正文对不上"就**立刻打开默认浏览器**把登录页推给你（微软官方设计如此）。
既然本程序会静默认证，你可以在界面底部勾上
**「拦截连接 WiFi 时自动弹出的浏览器登录页（需管理员权限）」**，
点一次 UAC 授权即可；重连 WiFi 或重启后不再弹。
命令行等价操作：`python GiwifiAutoLogin.pyw --portal-guard on`。

**Q：拦截之后有什么副作用吗？会不会把 Windows 的网络图标弄坏？**
关掉 NCSI 主动探测后，Windows 不再主动测连通性，所以：
① 任务栏网络图标**可能不再显示「无 Internet」的感叹号**；
② 少数依赖 NCSI 判断联网状态的应用（Microsoft Store、天气等）判断会偏慢。
网络本身、浏览器、游戏都不受影响，**本程序更是完全不受影响**（它用自己的探测点）。
不想要了就把勾取消（`--portal-guard off`），立刻恢复 Windows 默认行为。

**Q：拦截时提示「需要管理员权限」/ 弹了个 UAC 框，是怎么回事？**
这个开关改的是系统注册表（HKLM），Windows 规定必须管理员才能写。
所以勾选时会自动发起提权（弹一次 UAC），点「是」后由提权进程完成写入，
界面在几秒后回读注册表确认并告诉你结果。

**Q：程序会不会偷偷访问我的位置信息？**
改造前会（v1.8 已修）。原因是 Windows 把「读取 Wi-Fi 信息」算作一次**位置访问**，
而程序当时每 10 秒要查一次「当前连的是哪个 WiFi」，于是每 10 秒就访问一次位置。
现在只在**真正需要它决定做什么**的时候才查：已在线时不查、「不限制 WiFi」时不查、
窗口收进托盘时不刷新显示。实测后台常驻期间**位置访问 0 次**。
想自己核对：Win+R 输入 `winreg` 不方便的话，直接看
「设置 → 隐私和安全性 → 位置信息 → 最近活动」，本程序（pythonw.exe）的时间戳应当停留在上次手动操作的时刻。

**Q：开机后要多久才能上网？**
约几秒（v1.9 起）。旧版要 30 秒，因为里面有三段盲等（等 5 秒 → 开 Wi-Fi → 又等 6 秒 →
失败后退避 16 秒）。现在改成：**立即开 Wi-Fi → 直接发起连接 → 一旦就绪立刻继续**。
日志里会打印「Wi-Fi 准备用时 X 秒」可以直接看到。

**Q：为什么每次开机都弹一次「认证失败」？**
确实是常态：门户在客户端刚连上时**第 1 次认证经常被拒**（日志里 3 次开机都如此），
紧接着第 2 次就成功。所以「首次就弹」≈ 每次开机弹一下。
嫌吵就把 `alert_after_fails` 设成 `2` 或 `3`（失败到第 2/3 次才弹），设 `0` 则完全静默。

**Q：认证失败后程序会怎么做？**
**每 5 秒自动重试一次，直到成功**（v1.9 起）。成功后自动回到 10 秒的正常检测间隔。
注意：受门户自身「5 秒内不能重复提交」的限制，实际提交间隔约 6 秒 —— 这是不触发
门户限频前提下的最快节奏，再快会被回「操作过于频繁」。

**Q：为什么内存占用约 24 MB？还能更小吗？**
Python 解释器本身就要十几 MB，这是地板。已做的优化：用 `-S` 启动跳过 `site` 模块（省约 18 MB）、
`urllib` 改为按需加载（省约 4.8 MB）、取 SSID 走原生 API 不起子进程。
再往下只能换掉 tkinter 自绘界面，能省约 7 MB，但要重写整个 GUI，性价比很低。

## 十、可以拿去讲的技术点（比赛向）

1. **真实的协议逆向**：从「表单提交」到发现「整体 AES-CBC 加密」的完整推理链；关键证据是页面里的 `cryptoEncode()` 与 `aes.js` / `pad-zeropadding-min.js`。
2. **无需真账号的正确性验证方法**：利用服务端的错误分层（结构错误 vs 业务拒绝）做对照实验，这在题目里叫「黑盒差分探测」，是很硬核的一手。
3. **纯 Python 复刻 CryptoJS**：自己实现 AES-128-CBC + ZeroPadding，用 FIPS-197 与 NIST SP800-38A 标准向量自校验（见 `aes128.py` 的 `_selftest()`），证明实现正确。
4. **GUI 进程的「无控制台」陷阱（本项目的亮点之一）**：`pythonw.exe` 没有控制台，此时普通 `subprocess` 启动 `netsh` 会让 Windows **给子进程新建一个控制台窗口**，表现为黑框不停闪。必须带 `CREATE_NO_WINDOW` + `STARTUPINFO(SW_HIDE)`。而 GUI 卡死则是另一类问题——**在主线程做网络 IO**，实测主循环单次阻塞 63ms(P95 21ms) vs 修复前的 300ms~2s。
5. **工程鲁棒性**：门户限频 → 请求节流（还延伸出基于文件时间戳的**跨进程限频**）；
   失败 → **固定间隔快速重试**（实测比指数退避快 3 倍：16 秒 → 5 秒）；异常 → 不崩线程；日志轮转；单实例互斥。
6. **安全设计**：用 DPAPI 而非明文/简单异或存密码；**加密失败时拒绝降级**而不是静默写明文；密码明文不回显、不提供查看入口。
7. **零依赖交付**：AES、PNG/ICO 编码、`.lnk` 生成全部自己实现或内置单文件（`vendor/pylnk3.py`，LGPL 并保留许可证），不需要联网装包。
8. **适配高分屏**：窗口尺寸按 `winfo_screenwidth/height` 自适应，避免在 175% 缩放的笔记本上被裁切。
9. **Windows 命令输出的编码陷阱**：`netsh` 输出的是 **UTF-8**，而系统 ANSI 代码页是 GBK。
   写死按 GBK 解码会让中文全变乱码。正确做法是先严格按 UTF-8 试、失败再按 GBK 兜底
   （见 `winutil.decode_output`）。这个问题在只取 ASCII 内容时**不会暴露**，属于典型的潜伏 bug。
10. **扫描 WiFi 不能用 `netsh wlan show networks`**：笔记本一旦连上 AP，Windows 只做**定向扫描**
    （只为漫游找候选），netsh 于是常常只返回当前连接的那一个网络——实测 netsh 给 1 个、
    原生 `WlanScan()` 给 8 个。必须自己调 `wlanapi.dll` 触发全量扫描再读可用网络列表。
    附带好处：原生 API 直接给信号质量和 SSID 二进制，不用解析「信号 : 94%」这类本地化文本。
11. **「自动连接 WiFi」有个绕不过去的硬限制**：Windows 只能按**已保存的无线配置文件**连接
    （配置文件里含 WiFi 密码），程序无法凭空创建。所以自动连接只对「你之前手动连过」的网络有效。
    这个约束必须显式告知用户，而不是让它默默失败。
12. **安全设计要照顾用户认知**：v1.1 出于安全考虑让密码「不回显」，结果用户以为密码丢了，
    反复重输（`config.json` 的时间戳能佐证）。最终折中方案是——
    密文落盘 + 打开时自动填充（掩码） + 保存后不清空 + 明确的存储状态提示。
    安全措施如果让人觉得"东西不见了"，就会被绕过去，等于没有。
13. **同一个程序两个进程，却只能有一个托盘图标**（v1.10）：托盘图标是**全局唯一资源**
    （「通知区域」），后台实例和窗口各建一个就会出现两个一模一样的图标。
    解法不是让窗口去接管（那要跨进程搬句柄），而是**让后台那份主动让位**：
    给托盘加一个 `set_visible()` —— 只调 `Shell_NotifyIcon(NIM_DELETE / NIM_ADD)`，
    **不销毁窗口、不退出消息循环**，所以能反复切换、成本几乎为零；
    再用后台每秒读一次 `Global\GiwifiAutoLogin.Gui` 命名互斥体来判断「窗口在不在」。
    另外注意：托盘窗口过程回调跑在**托盘线程**里，菜单动作只能做线程安全的事
    （拨监控开关、写退出标记、另起进程），**绝不能弹模态框或发网络请求**，否则消息循环会卡死。
14. **PyInstaller 单文件模式下的「程序目录」陷阱**（v1.10 修）：
    onefile 打包后，主程序的 `__file__` 指向 `_MEIPASS`（临时解包目录），
    **进程退出就被删除**；而 `sys.executable` 才是指向真实 exe 的。
    如果日志、退出标记、崩溃记录按 `__file__` 落盘，就会出现
    「源码跑一切正常，打包后**日志凭空消失、多进程联动失效**」这种最难查的问题
    （而且两个进程的 `_MEIPASS` 还各不相同）。
    正确做法是运行时判断 `getattr(sys, 'frozen', False)`，打包后统一用 `sys.executable` 所在目录。
15. **「连接 WiFi 就弹浏览器」是 Windows 的强制门户探测，不是浏览器插件作乱**（v1.11）：
    NCSI 用**明文 HTTP** 请求 `msftconnecttest.com/connecttest.txt` 并校验响应正文；
    被网关劫持后 Windows 按设计**主动打开浏览器**推门户页（微软文档明写）。
    因为它必须能被中间人劫持才能工作，所以整个机制**依赖明文 HTTP** ——
    这既是它的弱点，也是定位它的线索：**看到"连上网络就被打开某个网页"，
    先去查 NCSI，而不是查浏览器或杀软**。拦截办法是关掉主动探测
    （策略项 `NoActiveProbe` / 服务参数 `EnableActiveProbing`），代价是
    Windows 不再显示「无 Internet」感叹号。
    另外：这类开关都在 HKLM，**普通权限写不了** —— 正确做法不是静默失败，
    而是检测到 `PermissionError` 后**主动提权重来一次**（`ShellExecuteW` 的 `runas` verb），
    写完还要**回读校验**，别只说"已写入"。
16. **"每 10 秒检查一次状态"和"不碰位置信息"可以不冲突**（v1.12）：
    需求是每 10 秒确认"Wi-Fi 连上没有"，但直接查 SSID 会被 Windows 记成一次位置访问，
    等于每 10 秒定位一次。解法是**换判据**：
    · 开关状态 → `WlanQueryInterface(radio_state)`（不触发位置）
    · 链路连上没有 → `GetAdaptersAddresses` 看 IEEE802.11 网卡的 `OperStatus`
    · 在不在校园网里 → 认证网关是否可达（**内网地址，在家不可达**，天然等价于"在校园网内"）
    只有"确认刚连上的是不是目标网络"才查一次 SSID。
    **教训：遇到"既想频繁检查又不想付出代价"的矛盾时，先想想能不能换一个更便宜的等价判据，
    而不是放弃检查或直接付代价。**
17. **`GetAdaptersAddresses` 会混进虚拟网卡**（v1.12 踩坑）：
    按 `IfType == 71 (IEEE802.11)` 找无线网卡时，Intel 网卡额外挂着两个
    `Microsoft Wi-Fi Direct Virtual Adapter`（供投屏用），**IfType 同样是 71、
    状态常年 Down，而且排在真正的物理网卡前面**。
    按"遇到第一个就下结论"写，就会永远返回"没连上"（实测如此，改成优先物理网卡才对）。
    同类坑：`Wi-Fi Direct` / `Virtual` 字样可以作为识别特征，但更稳的是
    **遍历完再判断**（"有没有任何一个是 Up"），而不是遇到就返回。
